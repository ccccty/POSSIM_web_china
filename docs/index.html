01 / PURPOSE

工程用途

本工程面向四类用途：机理演示、内核移植验证、桌面程序 Web 化方案参考，以及给定情景下的淹没范围初筛。

风暴潮机理演示

  • 按帧展示风场、气压、天文潮到淹没的完整链路
  • 同一场台风可逐小时查看中心位置、强度与淹没范围
  • 适用于教学、汇报与科普场景

教学 / 演示

  • 保留原 Fortran 内核调用路径，与 numpy 复现实现共用输入与后处理

03 / PIPELINE

计算流程

37 帧结果均由同一组公式在 1188×864 个格点上逐帧计算得到，不包含预渲染图像或插值动画。

  1. 01

    路径插值

    12–17 个 3/6 小时报点经 np.interp 分段线性插值至逐小时；移速与移向由相邻报点中心差分得到。

  2. 02

    Holland 风场

    梯度风 V(r) 由中心气压差与最大风速半径确定；四象限 r34/r50/r64 独立展开，保留台风不对称性。

  3. 03

    增水项叠加

    静压平衡的反气压项、风应力增水（拖曳系数随风速分段）与波增水（有效波高换算）逐格点相加。

  4. 04

    天文潮叠加

    M2 / S2 / K1 / O1 四个分潮按 η = Σ A·cos(ωt + φ) 合成，与风暴增水线性叠加为总水位。

  5. 05

    淹没判定

    总水位高于地面高程即判为淹没，水深为两者之差；随后执行 4 连通斑块过滤，去除不含海岸种子的孤立像元。

  6. 06

    分级成图

    按 0–0.33 / 0.5 / 1 / 2 / 3 / 5 m 七级配色渲染为 RGBA 图层，交 Leaflet 按经纬度范围叠加于底图。

04 / RESPONSE

最大风速与增水、淹没面积的响应关系

固定其余参数，将山竹路径的最大风速分别设为 75 / 90 / 105 / 120 / 135 / 150 / 165 kt，各计算一次，取峰值增水与峰值淹没面积。

峰值增水 m 峰值淹没面积 ha

结果说明

增水近似线性。Vmax 由 75 kt 增至 165 kt，峰值增水由 1.33 m 增至 2.36 m，增量与风速增量基本成比例。

面积呈阈值特征。150 kt 之后淹没面积由 21,193 ha 增至 34,484 ha，增长率明显提高：淹没范围受地面高程阈值控制，水位继续抬升会使大片低平地连片过水。

指标选择。研究区围田高程多在 0–1 m，总水位变化 0.1 m 即可引起面积大幅变化，故两套内核之间宜比较增水，面积仅作参考。

曲线由离线计算的 7 组结果生成；本地启动 server.py 可对任意参数实时计算。

05 / KERNELS

原 Fortran 内核的复用与对照

POSSIM 3.0 的物理内核为编译后的 storm_surge_physics.dll（x64，gfortran 静态链接），不依赖 GUI 与 .NET。 按原 C# 中的 P/Invoke 签名以 ctypes 调用即可运行，单帧 0.69 s，8 线程下 37 帧约 5–7 s。 在同一份 DEM 与同一帧输入下，两套内核可逐项对照。

指标（山竹 · Hour +020 · 增幅 3.8）numpy 复现原 Fortran
峰值增水1.664 m1.178 m
峰值淹没面积20,846 ha14,758 ha
最大淹没水深1.835 m1.466 m
37 帧耗时4.0–4.5 s5–7 s
实现方式numpy 向量化ctypes 调用 DLL

差异来源：径向衰减形式不同

将台风置于网格中心（Pc 900 hPa / Vmax 110 kt）：原内核 1.057 m，numpy 0.745 m，后者偏低 30%。
台风位于 119 km 外（山竹实际最近距离）：原内核 0.276 m，numpy 0.438 m，后者偏高 59%。

原内核的风增水为一次项 0.0291572 × W，与水深、风区无关；numpy 实现按风应力平方取二次项。近中心处二次项偏小、远场偏大，两曲线在中间距离交叉，因此差值不是常数偏移。

原内核子公式可由 scripts/probe_kernel_physics.py 复现：风增水 0.0291572·W，波增水 7.6e-4·W²（W>15 起算），拖曳系数分段线性。

数据项来源性质
